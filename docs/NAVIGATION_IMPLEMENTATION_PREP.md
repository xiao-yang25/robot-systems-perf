## 2. 固定测量边界与统计单位

**暂定第一条链：B接纳根导航请求→B形成并回传同一根请求的有效导航结果。** 输入时间记录在B取得处理责任的已确认边界，输出时间记录在B确认结果有效并完成约定回传的边界。具体点及回传含义仍需已绑定源码和现有运行依据核实。

这个边界不包含A的输入识别/Agent推理，不自动包含客户端收到结果或物理动作完成。若业务要求动作完成，应先证明F/G反馈的完成契约、根请求关联及B如何使用该反馈；不能把C的内部成功状态直接解释成物理完成。

### 根请求、attempt和嵌套请求

现场先填下面的转换表，不根据新UUID出现顺序猜测父子关系。

| 转换/边界 | 原ID与新ID的匿名字段 | 根ID/epoch/attempt来源与携带方式 | 证据及未决项 |
| --- | --- | --- | --- |
| A→B根请求 | 待填 | 待填 | 待填 |
| B→C导航任务 | 待填 | 待填 | 待填 |
| C→D/E工作及规划 | 待填 | 待填 | 待填 |
| C/D→B嵌套请求 | 待填；保留父子关系 | 待填；不得注册成新的根请求 | 待填 |
| F/G反馈→C/B结果 | 待填 | 待填 | 待填 |
| 重试/取消/重启 | 待填；明确复用与重新生成规则 | 待填；区分根epoch与执行进程代次 | 待填 |

根请求模式下，root_epoch由根ID的发行/接纳协议定义，并随上下文传递；不能在每个接收进程重新生成。进程重启身份另行记录。attempt编号归属及分配者需明确，嵌套请求携带root关联及parent关系，不创建隐式父子关系。

一次根接纳只有一个input；中间attempt失败和重试不是根output/drop。根请求最终有至多一个真实终态，未终结则保留未完成。根sample_id由已证明唯一的root_epoch与root_id无歧义编码，不因中间重试改变；编码方法、长度和原始ID映射留证。

若只能证明attempt级关联，应另定义“单次导航尝试”链及独立输入队列，不把attempt分位数称为根请求时延，也不同时向同一根sample_id添加多次input。根与尝试的分布分别解释。

### 结果分类

| 行为 | 根链设计处理 |
| --- | --- |
| B接纳前拒绝 | 单列offered/rejected依据，不在已接纳input分母；若要测接纳前拒绝，另定义输入更早的链 |
| B有效导航结果 | 仅在业务有效性和回传边界已确认时output(valid=true) |
| attempt失败后重试 | 原始阶段记录，根请求继续未终结，不发根终态 |
| 接纳后明确丢弃/取消/失败/超时 | 业务契约确认已终结且无有效交付时可映射drop(reason)；若确有无效交付，映射output(valid=false, reason)；不能同时输出两者 |
| 观察不到输出或观察截止 | unfinished，不生成drop，不推断网络丢包 |
| 迟到/重复/冲突终态 | 保留原始证据并报告冲突，不“取第一条”或删除记录来通过导入 |

业务失败不自动等于“无效交付”，两者以已核实的结果契约区分。跨线程交接显式携带不可变根上下文及attempt/parent关联；异步任务不能借用会失效的栈对象或依赖后来按名字查找身份。本包不实现任务结构修改。

## 3. 最小原始事件与现有导入格式的边界

真实源格式尚未确定。下表是设计待填项，不是新的公共schema，不生成示例业务事件或适配代码。根和尝试的来源、转换关系及阶段事件保留在原始证据；最终导入仍严格使用既有字段。

| 原始来源需证明的内容 | 适配到0.8.1的方式/限制 |
| --- | --- |
| root_id、root_epoch、attempt及parent/ID转换 | sample_id只编码选定统计单位；attempt和嵌套关系保留原始来源/适配依据，不给严格event对象增加字段 |
| 接纳、终态类型、有效性和原因 | type仅input/output/drop；input/drop的valid=true，无效output及drop必须有reason |
| 事件发生时CLOCK_MONOTONIC ns | monotonic_ns；不使用文件写入时间、墙钟或CTF ns_from_origin代替 |
| 事件发生时PID/starttime、boot、PID namespace | pid/starttime_ticks及context；历史身份未知保持unresolved，不按导入时当前身份补写 |
| 实际节点/domain与部署身份 | function_id/node、context.ros_domain_id及chain.deployment_version；匹配monitor声明和版本，domain未知不填0 |
| 窗口、独立接纳依据及实际导出损失 | window.start_ns/end_ns/expected_inputs/dropped_events；未知计数保留null |
| 来源格式、导出器版本及原始字节 | source.adapter=application_events_v1、tool_version、raw_sha256、synthetic=false；真实业务身份尚未确认时不能靠这个声明认证来源 |

当前context只支持一个boot、PID namespace、domain及linux_monotonic时间空间。异构namespace/domain或跨设备链在未证明可归一且兼容前不进入本契约；不得靠填写相同标签消除真实差异。没有时钟桥接时不跨源相减或关联资源窗口。

input与output可以都声明为B调度节点/功能，但drop/无效output必须同样满足output端点声明，不能把C/F/G日志按B身份直接改写。部署版本不能只用包版本替代真实构建绑定。资源引用只证明声明与观察身份一致，共享CPU/RSS不分摊给功能。

0.8.1严格拒绝未知字段；文本上限128字符，整数类型及范围、绝对node名、窗口覆盖、单输入单终态等校验保持不变。导出和raw-source各受16MiB限制，最多100000事件。若真实根ID编码或证据规模超限，先提出有证据的分窗/格式方案，不放宽校验或截断ID。模板见 [业务链](../configs/business-chain.template.json) 与 [业务事件](../configs/business-events.template.json)。

## 4. 独立接纳依据、窗口和导出损失

### 输入清单与观察窗口

独立接纳清单或生产计数必须来自B真实接纳状态，独立于用于导出事件的队列；不能从同一事件文件反推expected_inputs。优先保留唯一根键清单，可逐键检查遗漏、外来或替换；仅有计数时只能核对数量，不能证明每个ID完整对应。

接纳前拒绝不混入该计数。根模式重试不增加根接纳计数；attempt模式另建attempt计数。计数记录基线、最终值、epoch及重置/溢出规则；跨重启不能直接减两个累计值。

后续业务窗口需明确t_start、接纳队列截止t_accept_close、观察结束t_end及另行规定的导出排空截止t_drain。接纳截止只限定统计队列，不停止生产接纳；不得为本任务改变生产处理行为。

若接纳截止早于t_end，真实源需能可靠选出该固定队列，并保留边界筛选依据。仅纳入队列内input及同ID、发生于[t_start,t_end]的终态；窗口前已接纳任务和队列外输入单列，不能用过滤掩盖同一队列内的重复或冲突。窗口后迟到终态留原始来源，不倒改t_end，也不补造窗口内output。吞吐分母仍为整个声明事件窗口，不用排空耗时或完成样本首尾替代。

monitor资源观察必须覆盖所导入事件的身份和时间；当前观察包络不证明连续存活。新PID/starttime或退出记录缺失时保持unresolved。排空截止只控制导出完成，不延长业务事件窗口，已有队列内未完成请求也不因截止而变成drop。

### 有界非阻塞导出设计

热路径记录最小结构与实际发生时间，尝试放入有界队列；由独立写出层格式化并写盘。避免热路径同步写盘、flush或等待排空，不预设队列容量和采样预算，容量选择需后续有负载证据。

分别记录：

- buffer_full：未进入队列的导出事件数。
- write_failed：已进入队列但最终确认未成功写出的事件数；写尝试失败次数另列，不能重复计为丢事件。
- undrained：排空截止时尚未成功写出、且未归为write_failed的事件数。

这三类是导出事件计数，不是请求数或业务drop数。只在覆盖同一筛选范围、各类互斥且包含所有已知丢失路径时，才可求和写入window.dropped_events；任何范围、计数持久性或写出结果不明确，保持null并记录原因。部分写入、进程崩溃或计数记录本身丢失不能声明0。LTTng通道discard始终单独记录。

写出层的所有权、取消和关闭顺序需要在真实语言/运行模型确定后细化：停止该导出范围的新事件入队、在限定时间排空、记录最终计数与未完成状态，次要收尾错误不覆盖原始错误。不得阻塞或终止外部业务来保证排空。

## 5. 仓库适配器准备与替代方案

推荐在真实源格式确定后，增加独立适配模块，将已证明的接纳和终态转换为现有BUSINESS_EVENTS输入。沿用perfkit标准库核心，不把ROS依赖或业务专用语义塞入采样器，不修改现有身份与完整性检查。

适配前必须具备：源格式版本、原始来源、ID/终态规则、历史身份与时钟证据、独立输入依据、窗口和实际损失范围。输出保留来源字节摘要与转换依据，未解析记录隔离说明，不能丢弃异常记录后声称质量完整。

现实替代方案：已有日志字段完全够用时只做离线适配；字段不足时才提出最小埋点；根请求无法唯一终结时先分段测量或提出契约扩展，不将多输出硬压成单输出。暂缓完整分布式追踪、CTF业务推断和生产部署，以免在ID/终态未确认时实现错误模型。

## 6. 有限验收计划（尚未执行）

本次只交付计划。先核对源码/加载绑定、实际domain和业务契约；之后在另行允许的隔离范围检验下列逻辑，不在生产发送业务请求。

| 场景 | 必须证明的规则及证据 |
| --- | --- |
| 正常完成 | 独立接纳一次、ID跨交接不变、一个真实有效根终态、发生时身份/时钟可核对 |
| 接纳前拒绝 | 不产生根input，不进入接纳分母；拒绝原因和offered/rejected范围独立保留 |
| 接纳后失败 | 明确终态与真实原因；按业务语义选择drop或无效output，不重复计数 |
| 取消/超时 | 区分显式终结和仅等待超时；仅缺输出仍unfinished；未配置deadline不做deadline判定 |
| 重试/嵌套 | parent/root/attempt转换有依据，根仅一次input和至多一个终态，阶段失败不冒充根终态 |
| 重启 | root_epoch及恢复规则明确，事件PID/starttime记录新身份；历史依据不足保持unresolved |
| 重复/冲突/迟到 | 原始记录保留，现有导入拒绝或标无效；窗口和ID筛选有明确规则 |
| 导出异常 | 缓冲满、写失败、未排空独立且互斥计数；部分写入/崩溃/未知计数保留缺口，独立输入依据仍可核对 |

解析器用测试数据时必须标明测试来源，不能冒充现场业务。通过这些逻辑验收后，再另行安排一个固定真实业务窗口；原始输入、终态、身份、损失及覆盖有缺口即留证停止，不增加次数直到通过。CPU/周期/覆盖/扰动预算及稳定输入下的无采集对照是独立后续任务。
